# Glossy — Development Roadmap

## Phase 0 — Project Discovery

- **Goals:** Confirm business context, audience, content ownership, and constraints.
- **Deliverables:** Stakeholder notes, content inventory, unknowns list.
- **Done when:** Open questions have responsible decision paths and priorities; no business answers are invented in the documentation.

## Phase 1 — Product Requirements

- **Goals:** Validate the preliminary landing-page and page requirements.
- **Deliverables:** Approved requirements, content responsibilities, legal scope.
- **Done when:** MVP acceptance criteria, landing-page content sections, form boundary, content dependencies, and legal scope are agreed.

## Phase 2 — Design Research and Concept

- **Goals:** Research references and establish a distinctive visual direction.
- **Deliverables:** Moodboard/reference set, concept options, photography direction.
- **Done when:** One visual concept, asset direction, and content presentation approach are approved.

## Phase 3 — Design System and UI Planning

- **Goals:** Translate the concept into reusable foundations and states.
- **Deliverables:** Approved tokens, component inventory, responsive wireframes/designs.
- **Done when:** Core screens, responsive states, form states, and UI ownership boundaries are ready for implementation.

## Phase 4 — Project Setup

- **Goals:** Configure the reviewed frontend toolchain.
- **Deliverables:** React/TypeScript/Vite setup, quality tooling, initial scripts.
- **Done when:** The reviewed setup exists, local checks run successfully, and the production build is reproducible.

## Phase 5 — Core Layout and Routing

- **Goals:** Implement shared layout, navigation, route handling, and 404.
- **Deliverables:** Root layout, navigation, landing and legal route shells.
- **Done when:** Routes, responsive navigation, and keyboard behavior meet criteria.

## Phase 6 — Landing Page Sections

- **Goals:** Build the six approved content sections and shared header/navigation with real approved content/assets.
- **Deliverables:** Responsive sections, portfolio presentation, rental section.
- **Done when:** Section acceptance criteria, responsive behavior, accessibility checks, and visual review pass.

## Phase 7 — Forms and Validation

- **Goals:** Deliver an approved contact submission path.
- **Deliverables:** Form schema, accessible states, backend/provider integration.
- **Done when:** Valid and invalid flows are tested end-to-end.

## Phase 8 — Legal Pages and SEO

- **Goals:** Add approved legal content and metadata.
- **Deliverables:** Privacy policy, terms if required, titles, descriptions, social metadata.
- **Done when:** Legal owner approves content and SEO checks pass.

## Phase 9 — Testing and QA

- **Goals:** Validate behavior, accessibility, responsiveness, and content.
- **Deliverables:** Automated tests, manual QA record, issue fixes.
- **Done when:** Release-blocking defects are resolved.

## Phase 10 — CI/CD

- **Goals:** Automate repeatable checks and previews.
- **Deliverables:** GitHub Actions workflows and preview configuration.
- **Done when:** Approved changes receive reliable checks and preview builds.

## Phase 11 — Production Deployment

- **Goals:** Configure hosting, domain, HTTPS, and production environment.
- **Deliverables:** Production deployment and runbook.
- **Done when:** Post-deployment verification passes.

## Phase 12 — Final Review and Release

- **Goals:** Confirm business, legal, design, quality, and operational readiness.
- **Deliverables:** Release checklist, known-issues log, handoff notes.
- **Done when:** Stakeholders approve release and rollback/contact ownership is clear.
